# Pipeline details

Steps 01–05 were generated by `install_sfari_pipeline_v4.sh` (now in the archive); they are versioned here
as plain files. All paths derive from `$SFARI_ROOT` (default `/sc/arion/projects/ad-omics/raphael/SFARI`).

## Steps 01–05: build the concatenated, annotated count matrix

| Step | Script | Writes (in `$SFARI_ROOT/pipeline_output/`) | LSF resources (jobs/run_pipeline_01-05.sh) |
|---|---|---|---|
| 01 | `01_inspect_datasets.py` | `dataset_inspection.json` (where the raw counts are: `X`, `.raw.X`, layer) | 350 GB, 2 h |
| 02 | `02_build_gene_universe.py` | `gene_manifest.parquet`, `filtered_genes.txt` | 3650 GB, 24 h |
| 03 | `03_concatenate_datasets.py` | `concatenated_raw.h5ad` (outer join over genes) | 1100 GB, 144 h |
| 04 | `04_annotate_celltypes.py` | `concatenated_annotated.h5ad` (`cell_type_merged`, `cell_type_supercategory`) | 1100 GB, 72 h |
| 05 | `05_annotate_devstage.py` | `sfari_final.h5ad` (coarse developmental categories) | 1100 GB, 72 h |

Each step writes a checkpoint (`pipeline_output/checkpoints/<step>.done`) and is skipped when it exists;
step 03 also checkpoints each dataset (`dataset_<key>.done`). To redo a step or one dataset, delete its
checkpoint and resubmit.

```bash
bash jobs/run_pipeline_01-05.sh          # submits the five steps as chained LSF jobs
```

### Configuration (`pipeline/config.py`)

| Setting | Meaning |
|---|---|
| `ENSEMBL_DATASETS` / `SYMBOL_DATASETS` | key → h5ad; genes as Ensembl IDs (mapped with `gene_maps/<key>_gene_map.csv`) or symbols |
| `MTX_DATASETS`, `COMBINED_MTX`, `MTX_DATASET_MAPPING` | Raj, Davie, Sziraki and Velmeshev (2019), which arrive as one merged MTX |
| `DATASET_META` | key → display name (`"Author (Year)"`) and organism |
| `DATASET_LAYER_OVERRIDE`, `DATASETS_TO_ROUND` | He (2024): `counts_lengthnorm` layer, rounded |
| `EXTERNAL_METADATA` | external cell annotations joined by barcode |
| `CELLTYPE_COLUMNS` | priority of author cell-type columns merged in step 04 |
| `GENE_EXCLUDE_PREFIXES`, `GENE_EXCLUDE_PATTERNS`, `MIN_DATASETS_PER_GENE` | gene filtering (spike-ins and unmapped IDs only; outer join) |

Datasets from CELLxGENE are added automatically from `data/cellxgene/registry.json` (see
`pipeline/cellxgene/README.md`). To add another dataset by hand: put raw counts in `X` (or `.raw.X`),
add it to `SYMBOL_DATASETS` or `ENSEMBL_DATASETS` and `DATASET_META`, and add its sample and time-point
columns to `DATASET_SAMPLE_COL` / `DATASET_TIME_COL` in `prep_sfari_data_v8.py` and
`create_merged_columns.py`.

### Troubleshooting

- **Out of memory**: raise `rusage[mem=...]` for the step in `jobs/run_pipeline_01-05.sh`.
- **No raw counts found**: check `dataset_inspection.json`; use a source file with counts in `X`, `.raw.X`
  or a layer (and `DATASET_LAYER_OVERRIDE`).
- **Genes left as Ensembl IDs**: provide `gene_maps/<key>_gene_map.csv` with `ensembl_gene_id,symbol`.

## Step 06: CONCORD integration and label transfer

`06_integrate_concord.py` replaces the scVI → scANVI cells of `notebooks/01052026_SFARIExplorer_data-prep.ipynb`.

| | Before (scVI/scANVI) | Now (CONCORD 1.0.13) |
|---|---|---|
| Batch | `batch_key='dataset'` | `domain_key='dataset'`, dataset-aware minibatches (`p_intra_domain=1`) |
| Features | HVGs | seurat_v3 HVGs (batch = dataset) among orthologs detected in every species |
| Labels | scANVI, unlabelled = `Unknown` | CONCORD classifier head, unlabelled = `Unknown`, 10 % held-out evaluation |
| Latent | `X_scANVI` | `X_concord` (100 dims) |
| Output | `combined_scanvi_label_transfer.h5ad` | `combined_concord_label_transfer.h5ad` |

Outputs in `data/concord/`: `concord_label_transfer_qc.csv` (held-out precision/recall per cell type,
accuracy per dataset), `concord_class_probabilities.parquet`, `concord_cell_annotations.parquet`,
`gene_detection_by_species.parquet`, `concord_features.csv`, `umap_subsample.parquet`, `build_info.json`.
`obs['predicted_labels']` keeps harmonised author labels where they exist and uses the CONCORD prediction
otherwise (`obs['label_source']`); `--overwrite-author-labels` reproduces the scANVI behaviour.

```bash
bsub < jobs/run_integrate_concord.lsf     # GPU node; CPU works but is slow
```

## Steps after integration

```bash
bsub < jobs/run_postprocess.lsf           # pseudobulk -> metadata -> ages -> correction -> parquets
```

| Step | Script | Reads | Writes |
|---|---|---|---|
| pseudobulk | `prep_sfari_data_v8.py --stage 1` | CONCORD output, `concatenated_annotated.h5ad` | `pseudobulk_counts.csv`, `pseudobulk_meta.csv`, `umap_subsample.parquet` |
| metadata | `add_missing_metadata.py`, `create_merged_columns.py` | CONCORD output | per-cell h5ad with merged sample/time columns |
| ages | `normalize_age.py` | `pseudobulk_meta.csv`, per-cell h5ad | `pseudobulk_meta_numeric_time.csv` |
| correct | `correct_within_org.R` (R env: `envs/r_correction.yml`) | counts + numeric-time metadata | `corrected_expression.csv` (voom, ComBat within species) |
| parquets | `prep_sfari_data_v5.py --stage 2` | corrected expression + metadata | `expression_summaries`, `temporal_expression`, ... (long format) |

All of them read and write `$SFARI_EXCHANGE_DIR` (default `data/r_exchange`; `prep_sfari_data_v8.py` alone
defaults to `data/r_exchange_v3`, so set the variable when running the steps individually).
`prep_sfari_data_v8.py --stage 3` is an alternative to the last two steps (limma `removeBatchEffect` across
datasets instead of ComBat within species). `transfer_annotations.py` and `generate_pseudobulk_expression.py`
are older single-purpose versions of these steps.
